# oop-project
# 📦 캠퍼스 유휴자원 실시간 공유 플랫폼 (최종 설계 보고서)

---

## 1. 시스템 개요

본 시스템은 캠퍼스 내 학생들이 보유한 유휴 자원을 시간 단위로 공유할 수 있도록 하는 플랫폼이다.  
사용자는 자신의 물품을 등록하고, 필요한 다른 사용자는 이를 일정 시간 동안 대여할 수 있다.

또한 본 시스템은 아이템의 상태를 객체로 관리하는 상태 패턴(State Pattern)과,  
상황에 따라 정책을 유연하게 적용할 수 있는 전략 패턴(Strategy Pattern)을 적용하여  
확장성과 유지보수성을 고려한 객체지향 시스템으로 설계되었다.

---

## 2. 핵심 기능

### 2.1 회원 기능 (User)

사용자는 시스템의 기본 단위로, 다음과 같은 기능을 수행한다.

- 아이템 등록
- 아이템 대여 요청
- 거래 진행
- 리뷰 작성
- 매너온도 변화

#### 동작 흐름
회원 생성 → 아이템 등록 → 대여 요청 → 거래 → 리뷰 → 온도 변화

#### 객체지향 설계
- 캡슐화: 온도 값은 직접 수정하지 않고 메서드를 통해 변경
- 단일 책임 원칙(SRP): 사용자 정보와 온도 로직을 분리

---

### 2.2 매너온도 시스템 (Temperature)

매너온도는 사용자 신뢰도를 나타내는 지표로, 거래 결과에 따라 변화한다.

#### 동작 방식
- 거래 성공 시: 온도 증가
- 문제 발생 시: 온도 감소

#### 객체지향 설계
- SRP 적용: 온도 관리 책임을 User에서 분리
- 유지보수성 향상: 정책 변경 시 Temperature만 수정

---

### 2.3 아이템 관리 기능 (Item)

아이템은 공유 대상 자원을 의미하며, 다음 정보를 포함한다.

- 이름
- 소유자
- 가격
- 위치
- 상태

#### 동작 흐름
아이템 등록 → Available 상태 → 대여 요청 → 상태 변경 → 반납 → 상태 초기화

#### 객체지향 설계
- 인터페이스 활용 (Rentable, Shareable)
- 상태 캡슐화 (외부에서 직접 상태 변경 불가)

---

## 3. 상태 기반 대여 시스템 (State Pattern)

### 3.1 개요

아이템은 항상 하나의 상태를 가지며, 상태에 따라 수행 가능한 행동이 달라진다.

### 3.2 상태 종류

- Available (대여 가능)
- Reserved (예약됨)
- Rented (대여 중)

### 3.3 상태 전이

Available → Reserved → Rented → Available

### 3.4 동작 흐름

- 대여 요청 시: Available → Reserved  
- 대여 시작 시: Reserved → Rented  
- 반납 시: Rented → Available  

### 3.5 객체지향 설계

- 상태를 객체로 분리하여 관리
- 다형성을 활용하여 상태별 행동 구현

#### 적용 효과
- OCP (개방-폐쇄 원칙) 만족
- 상태 추가 시 기존 코드 수정 불필요
- 유지보수성 향상

---

## 4. 거래 시스템 (Transaction)

### 4.1 개요

거래는 사용자 간 자원 대여 과정을 관리하는 기능이다.

### 4.2 동작 흐름

대여 요청 → Transaction 생성 → execute() 실행 → 아이템 상태 변경

### 4.3 구조

- Transaction (추상 클래스)
- Rental (대여)

### 4.4 객체지향 설계

- 상속 구조 활용
- 다형성 기반 execute() 구현

#### 확장성
향후 Exchange(교환) 기능 추가 가능

---

## 5. 패널티 시스템 (Strategy Pattern)

### 5.1 개요

사용자가 규칙을 위반할 경우 패널티가 적용되며, 상황에 따라 정책이 달라진다.

### 5.2 패널티 종류

- 연체
- 파손
- 미반납

### 5.3 동작 흐름

문제 발생 → 정책 선택 → apply() 실행 → 온도 감소

### 5.4 객체지향 설계

- 전략 패턴 적용
- 정책을 객체로 분리하여 유연하게 변경 가능

#### 적용 효과
- 정책 추가 및 변경 용이
- if문 제거로 코드 가독성 향상

---

## 6. 리뷰 시스템 (Review)

### 6.1 기능 설명

거래 완료 후 사용자는 상대방을 평가할 수 있다.

### 6.2 동작 흐름

거래 완료 → 리뷰 작성 → 온도 반영

### 6.3 객체지향 설계

- 사용자와 리뷰 객체 간 관계 형성
- 책임 분리

---

## 7. 시간 기반 대여 시스템 (TimeSlot)

### 7.1 기능 설명

아이템은 시간 단위로 대여되며, 특정 시간 구간 동안만 사용 가능하다.

### 7.2 동작 흐름

시간 선택 → TimeSlot 생성 → 해당 시간 동안 대여

### 7.3 객체지향 설계

- 시간 관리 책임 분리
- 재사용 가능한 구조

---

## 8. 위치 기반 검색 (Location)

### 8.1 기능 설명

사용자는 가까운 위치의 아이템을 검색할 수 있다.

### 8.2 동작 흐름

사용자 위치 확인 → 아이템 위치 비교 → 필터링

### 8.3 객체지향 설계

- 위치 정보를 별도 객체로 분리
- 확장성 확보 (GPS 연동 가능)

---

## 9. 전체 시스템 실행 흐름

1. 사용자 A가 아이템을 등록한다 (상태: Available)

2. 사용자 B가 아이템을 검색한다

3. 대여 요청을 수행한다  
→ 상태: Available → Reserved

4. 대여가 시작된다  
→ 상태: Reserved → Rented

5. 사용 후 반납한다  
→ 상태: Rented → Available

6. 리뷰를 작성한다  
→ 매너온도 상승

7. 문제 발생 시  
→ 패널티 적용 → 매너온도 감소

---

## 10. 객체지향 설계 원칙 적용

| 원칙 | 적용 내용 |
|------|-----------|
| SRP | Temperature 클래스 분리 |
| OCP | 상태 패턴, 전략 패턴 적용 |
| 캡슐화 | 상태 및 온도 직접 접근 제한 |
| 다형성 | State 및 Strategy 활용 |
| 상속 | Transaction 구조 |

---

## 11. 결론

본 시스템은 단순한 대여 서비스를 넘어,  
상태 패턴을 통한 동적 상태 관리, 전략 패턴을 통한 정책 유연성,  
그리고 객체 간 책임 분리를 통해 높은 확장성과 유지보수성을 갖춘  
객체지향 기반 공유 경제 플랫폼이다.

또한 기존 대학 시스템이 제공하지 못하는 개인 자원 공유를 가능하게 하여,  
경제적, 환경적, 학습적 측면에서 긍정적인 효과를 기대할 수 있다.
